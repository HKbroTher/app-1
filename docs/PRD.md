# 九宫展 · 产品需求文档（v0.1）

> 暂定名，可替换。限时 9 图数字展陈社区。本文覆盖：定位、角色与流程、页面结构、业务规则、状态与权限、MVP 范围、待决事项、视觉规范、技术栈。

---

## 1. 产品定位与目标用户

**一句话定位**：一个让每个人都能策划「限时 9 图展览」的移动端展陈社区——作品有开展、有闭展、有档期，像真正的展览一样被期待、被观看、被收藏。

**与 Instagram / 小红书的差异**

| | 普通图片社区 | 本产品 |
|---|---|---|
| 内容单位 | 单帖、无限流 | 一场展览 = 固定 9 张 + 标题 + 介绍 |
| 时间属性 | 永久在线 | 有开展/闭展时间，过期即归档，仅策展人可看全 |
| 关系核心 | 关注 → 刷动态 | 关注 → 预约 → 开展提醒 → 观展 |
| 浏览体验 | 信息流 | 单展沉浸式、逐张切换、悬浮纵深的数字展陈 |

**目标用户**

1. **视觉创作者 / 摄影爱好者**（核心供给）：有成组作品，希望以「系列」形式被认真观看，而非被流量算法稀释。
2. **插画师、设计师、学生作品集**：需要有仪式感的阶段性发布（毕业展、个人小展、系列首发）。
3. **观展者 / 审美型用户**（核心消费）：喜欢精致内容、愿意为喜欢的策展人「预约」并准时观看。
4. 次要：品牌/工作室做限时视觉发布（MVP 不专门支持商业功能）。

**核心价值**：稀缺性（限时）+ 仪式感（预约、开展）+ 作品优先的展陈质感。

## 2. 用户角色与核心用户流程

### 2.1 角色

| 角色 | 定义 |
|---|---|
| 策展人 | 某场展览的创建者。任何注册用户都可成为策展人。 |
| 关注者（Follower） | 关注了该策展人的用户；可预约其展览。 |
| 互关好友 | 双方互相关注；可私信。 |
| 路人 | 已登录但未关注该策展人的用户。 |
| 被拉黑用户 | 被策展人拉黑；对策展人不可见（见 §4.8）。 |
| 平台运营（后台） | 处理举报、下架违规展览（MVP 可只做数据库层操作，无后台界面）。 |

### 2.2 核心流程

**A. 策展人发布展览**
Post → 选择 9 张图片（排序，第 1 张为封面）→ 填标题、介绍 → 设置开展/闭展时间 → 预览 → 发布 → 展览进入「待开展」→ 出现在策展人主页「即将开展」。

**B. 观众发现与观展**
Explore 浏览正在展出的展览 → 进入展览浏览页 → 逐张切换 9 张 → 点击策展人头像/「关注」→ 关注策展人。

**C. 关注 → 预约 → 提醒 → 观展**
在策展人主页看到「即将开展」→（已关注）点「预约」→ 开展前 30 分钟收到推送 → 开展时点进推送直达展览 → 观展。未关注时点「预约」→ 弹出「关注后即可预约」→ 一键关注并预约。

**D. 策展人取消 / 提前闭展**
待开展期间：展览详情 → 「取消展览」→ 二次确认 → 已取消（预约者收到/不收到通知，见 §4.5）。
展出中：「提前闭展」→ 二次确认 → 立即归档。

**E. 归档回看**
展览结束 → 自动进入策展人 My Profile「已归档」→ 策展人可看全部 9 张；他人仅看到封面卡片。

**F. 私信**
互关后，在对方主页点「私信」→ 进入对话。

## 3. 页面结构与主要操作

全局：底部无边框导航栏（Explore / Post / Message / My Profile），选中项下方的发光渐变光条从当前项丝滑弹簧移动到新选中项。Post 不切换标签，而是从底部弹出全屏创建流程。展览浏览页、对话页等沉浸页隐藏底栏。

### 3.1 Explore

```
┌─────────────────────────────┐
│ Explore              [🔍]   │  ← 右上角：按用户 ID 搜索
│ [全部] [即将闭展] [关注的人] │  ← 毛玻璃分段筛选（MVP 可只做前两个）
│ ┌──────────┐ ┌──────────┐   │
│ │ 封面     │ │ 封面     │   │  ← 双列展览卡片：封面 + 标题 + 策展人
│ │ 剩余 3h  │ │ 剩余 2d  │   │     + 剩余时间胶囊（展出中）
│ └──────────┘ └──────────┘   │
└─────────────────────────────┘
```

- 内容：仅「展出中」的展览（排除拉黑关系）。
- 默认排序：MVP 按开展时间倒序；「即将闭展」按剩余时间升序。
- 操作：点卡片进入展览浏览页；下拉刷新；无限加载。
- **搜索页**：输入用户 ID（精确/前缀匹配）→ 用户结果列表（头像、ID、昵称、关注按钮）→ 进入对方主页。

### 3.2 Post（创建展览）

分步表单（顶部步骤指示 1/3）：

1. **选图**：从相册多选，必须正好 9 张；3×3 网格预览，长按拖拽排序，第 1 张标记「封面」；可替换单张。不足 9 张时「下一步」禁用并提示「还差 N 张」。
2. **信息**：标题（必填，≤30 字）、介绍（选填，≤500 字）。
3. **档期**：开展时间、闭展时间选择器；实时显示「展期 X 天 Y 小时」「锁定期从 HH:mm 开始，之后不可取消」。
4. **预览并发布**：以展览浏览页样式预览 → 发布。上传过程显示进度，失败可重试；中途退出保存本地草稿（MVP 本地草稿即可）。

### 3.3 My Profile（及他人主页）

```
┌─────────────────────────────┐
│ 头像  昵称  @user_id     [⚙] │
│ 简介                         │
│ 展览 12 · 关注者 340 · 关注 88│ ← 点击进入关注者/关注列表
│ [编辑资料] / 他人: [关注][私信]│
│ ── 即将开展 · 展出中 · 已归档 · 预约 ── │ ← 毛玻璃分段 Tab
│ 展览卡片网格                  │
└─────────────────────────────┘
```

- **即将开展**：待开展/锁定期的展览（他人可见封面、标题、开展时间、「预约」按钮）。
- **展出中**：正在展出的展览。
- **已归档**：已结束（含提前闭展）的展览。他人只见封面卡片，带「已闭展」标识。
- **已取消**（仅本人可见，可放在「即将开展」Tab 底部折叠区或设置中）。
- **预约**（仅本人可见）：我预约的展览列表，按开展时间排序，每项可「取消预约」；展示预约状态（待开展 / 已开展 / 已取消 / 已结束）。
- 右上角：设置（账号、通知开关、黑名单、退出登录）、消息入口（私信列表 + 系统通知）。

> 消息中心入口：MVP 放在 My Profile 右上角（铃铛/信封图标，带未读红点），不占用底栏。

### 3.4 展览浏览页（核心体验）

```
┌─────────────────────────────┐
│ [←]   展览标题        [···]  │  ← 顶部毛玻璃条
│                              │
│      ╭─────────────────╮     │
│      │                 │     │  ← 当前作品：悬浮卡片，柔和投影 +
│      │     作  品       │     │     背景取色光晕，轻微呼吸浮动
│      │                 │     │
│      ╰─────────────────╯     │
│  ‹ 前后作品缩小、后退、半透明 › │  ← 3D 纵深层叠，左右滑动切换
│           03 / 09            │  ← 毛玻璃序号胶囊
│ ● ● ◉ ● ● ● ● ● ●            │  ← 进度点（可点击跳转）
│ [头像 策展人 · 关注]  剩余 5h │  ← 底部毛玻璃信息条
└─────────────────────────────┘
```

- 操作：左右滑动 / 点击两侧切换；双指缩放看细节；点击作品切换「沉浸模式」（隐藏所有 UI）；上滑或点「展览介绍」展开介绍面板。
- 策展人视角的 [···]：取消展览（待开展且未锁定）、提前闭展（展出中）、分享。
- 观众视角的 [···]：分享、举报、拉黑策展人。
- 归档展览（非策展人）：只展示封面 + 「本展已闭展」毛玻璃遮罩，不提供切换。

## 4. 业务规则

时间约定：所有时间由**服务端**判定，存储为 UTC，按用户本地时区显示。下文 `T_start` = 计划开展时间，`T_end` = 计划闭展时间，`T_lock` = `T_start − 30 分钟`。

### 4.1 创建展览

- 必须正好 9 张图片；第 1 张为封面（可拖拽调整）。
- 标题必填 ≤30 字；介绍选填 ≤500 字。
- `T_start` 必须晚于发布时刻 **至少 1 小时**（保证发布后有 ≥30 分钟可取消窗口与预约窗口）。【待定参数】
- 开展时间：发布后至少 1 小时、14 天以内，5 分钟为步进；先选日期再选当天时间（滚轮）。【已定 2026-10-07】
- 展期 `T_end − T_start`：1–48 小时，按整小时选择（滚轮，默认 24 小时）。【已定 2026-10-07】
- 同一策展人同时处于「待开展 + 展出中」的展览上限：MVP 建议 5 场，防刷。【待定参数】
- 图片：单张 ≤20MB，上传前客户端压缩到长边 ≤2560px；仅 JPG/PNG/HEIC/WebP。
- 发布后编辑：`T_lock` 之前可修改标题、介绍、图片；**时间不可改**（如需改期 = 取消后重发）。锁定期及之后均不可编辑。【建议，上线前确认】

### 4.2 状态自动流转

由服务端定时任务（每分钟）+ 读取时实时计算双保险：

- `now ≥ T_lock` 且状态为「待开展」→「锁定期」，同时触发提醒。
- `now ≥ T_start` →「展出中」。
- `now ≥ T_end` →「已归档（自然结束）」。

### 4.3 关注

- 关注无需对方同意（MVP 不做私密账号）。
- 可在：展览浏览页底部信息条、用户主页、搜索结果中关注。
- 取消关注的连带影响：
  - 自动取消我对该策展人所有**未开展**展览的预约（因为预约以关注为前提），未发出的提醒一并撤销。
  - 若原为互关，私信对话变为只读（§4.7）。

### 4.4 预约

- 前提：已关注该策展人；不能预约自己的展览。
- 可预约时间窗：展览「待开展」或「锁定期」，即 `T_start` 之前。
- 在锁定期（提醒已发出后）预约：预约成功但**不再补发提醒**，界面提示「即将开展，到时直接来看」。【建议】
- 用户可在 `T_start` 前随时取消预约；取消后对应未发提醒同步撤销。
- 展览开始后预约记录状态变为「已开展」，保留在「预约」列表中供回看入口；展览结束后变为「已结束」。

### 4.5 提醒

- 在 `T_lock`（开展前 30 分钟）向所有有效预约者发送推送 + 站内通知：「你预约的《XX》将在 30 分钟后开展」，点击直达展览页（未开展时显示倒计时）。
- 发送前校验：展览状态仍为待开展/锁定期、预约有效、双方无拉黑关系。
- 用户关闭系统推送时仍写入站内通知。

### 4.6 取消、锁定、提前闭展、归档

**取消（仅限开展前）**
- 策展人可在 `T_lock` **之前**随时取消；服务端以 `now < T_lock` 原子判断（与提醒任务使用同一时间基准），从 `T_lock` 起进入锁定期，取消按钮置灰并说明「开展前 30 分钟内不可取消」。
- 取消后：展览状态「已取消」，不进入归档，从他人主页消失；所有预约状态变为「展览已取消」。
- 提醒处理：
  - **提醒尚未发出**（正常情况，因为取消只能发生在 `T_lock` 之前）→ 撤销全部待发提醒，并给预约者发一条站内通知「《XX》已被策展人取消」（不推送，避免打扰）。【建议】
  - **提醒已发出**（理论上仅出现在：定时任务与取消请求的竞态，或平台运营强制下架）→ 必须向所有已预约用户发送**推送 + 站内**取消通知。
- 已取消展览仅策展人自己可在「已取消」中查看全部 9 张，可「以此为模板重新发布」（MVP 可选）。

**锁定期（`T_lock` ≤ now < `T_start`）**
- 不可取消、不可编辑；仍可被预约（无提醒）。
- 若策展人确有问题，只能等开展后立即「提前闭展」。

**提前闭展（仅展出中）**
- 策展人在 `T_start` 后、`T_end` 前可提前闭展，二次确认。
- 闭展即时生效：状态变为「已归档（提前闭展）」，记录实际闭展时间 `T_closed`，按已结束展览处理（权限同 §5）。
- 预约记录：保留，状态改为「已结束」，不删除（用于用户回看自己预约过什么）。
- 已发送的提醒：不撤回（推送无法撤回）；用户点开旧提醒时直达展览页，展示「本展已提前闭展」+ 封面。
- 额外通知：给**已预约但尚未打开过该展览**的用户发一条站内通知「《XX》已提前闭展」，不推送。【建议，可后定】
- Explore 中即时移除。

**归档**
- 自然结束（`T_end`）或提前闭展 → 自动归档到策展人 My Profile「已归档」。
- 归档不可恢复为展出中，不可再编辑；策展人可删除归档展览（MVP 可选）。
- 已取消展览**不进入**归档。

### 4.7 私信

- 发起和发送的前提：**双方互相关注**。非互关用户主页不显示「私信」按钮。
- MVP 支持文字消息（+ 可选分享展览卡片），不做图片/语音。
- **取消关注后（任一方）**：
  - 双方已有对话**保留**，历史消息双方仍可查看；
  - 对话变为只读，输入框替换为提示「互相关注后可继续聊天」；
  - 重新互关后自动恢复可发送。
- **拉黑后**：
  - 自动解除双方的关注关系（双向），并取消被拉黑者对拉黑者展览的所有预约；
  - 对话对**双方都只读**；拉黑方可从列表中删除该对话（仅删除自己一侧的显示），被拉黑方仍保留历史但无法发送，且不提示「被拉黑」，仅显示「无法发送消息」；
  - 历史消息服务端保留（用于举报取证），不因拉黑而删除；
  - 解除拉黑**不会**自动恢复关注，需重新互关才能私信。

### 4.8 拉黑的其他影响

- 被拉黑者无法看到拉黑者的主页、展览（Explore 中也过滤），搜索不到拉黑者；反之拉黑者也不会在 Explore 看到对方。
- 不能互相关注、预约、私信。

## 5. 展览状态与查看权限

### 5.1 状态定义

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| 待开展 `scheduled` | 发布成功 | 到 `T_lock` → 锁定期；策展人取消 → 已取消 |
| 锁定期 `locked` | `now ≥ T_lock` | 到 `T_start` → 展出中 |
| 展出中 `live` | `now ≥ T_start` | 到 `T_end` → 已归档；提前闭展 → 已归档 |
| 已归档 `archived` | 自然结束 / 提前闭展（字段 `end_reason = natural / early`） | 终态 |
| 已取消 `cancelled` | 开展前由策展人取消 / 平台下架 | 终态 |

> 「锁定期」对外展示仍为「即将开展」，仅在策展人视角显示锁定说明。

### 5.2 查看权限矩阵

| 状态 | 策展人本人 | 关注者 | 路人 | 被拉黑者 |
|---|---|---|---|---|
| 待开展 / 锁定期 | 全部 9 张 + 管理操作 | 封面、标题、介绍、开展时间；可预约 | 封面、标题、介绍、开展时间；预约需先关注 | 不可见 |
| 展出中 | 全部 9 张 + 提前闭展 | 全部 9 张 | 全部 9 张（Explore 可见） | 不可见 |
| 已归档 | 全部 9 张 + 介绍 + 数据 | **仅封面** + 标题、展期、「已闭展」 | **仅封面** + 标题、展期、「已闭展」 | 不可见 |
| 已取消 | 全部 9 张（仅在「已取消」区） | 不可见；预约列表显示「已取消」占位 | 不可见 | 不可见 |

**权限必须由服务端强制**：非封面图片的访问 URL 只能通过有权限校验的接口签发（短时效签名链接），客户端隐藏不算权限控制。归档后旧签名链接在过期后失效（建议有效期 ≤1 小时）。

## 6. MVP 范围（第一版）

**包含**
- 账号：手机号或邮箱注册登录、唯一用户 ID（可设置一次）、昵称、头像、简介。
- Explore：展出中展览双列流、按用户 ID 搜索。
- Post：选 9 图 + 排序 + 标题介绍 + 开展闭展时间 + 预览发布；本地草稿。
- 展览浏览页：悬浮纵深切换、序号 `03 / 09`、进度点、缩放、介绍面板、关注按钮。
- 状态机自动流转、锁定期、取消、提前闭展、自动归档、权限矩阵（服务端强制）。
- 关注 / 取消关注、关注者与关注列表。
- 预约 / 取消预约、我的预约列表。
- 推送提醒（开展前 30 分钟）+ 站内通知中心（预约提醒、取消通知）。

## 8. 视觉规范（Design Tokens 初稿）

**原则**：黑色为底，作品为主角；所有 UI 容器是「悬浮在作品之上的毛玻璃」；彩色只出现在强调处（选中态、主按钮、进度、头像环），不与作品争色。

| Token | 值 |
|---|---|
| 背景 `bg` | `#050505`（纯黑略提亮，避免 OLED 拖影） |
| 玻璃面 `glass` | `rgba(255,255,255,0.08)` + 背景模糊 24–40 |
| 玻璃高亮 `glassStrong` | `rgba(255,255,255,0.14)` |
| 玻璃描边 | 1px `rgba(255,255,255,0.12)`，顶部内高光 `rgba(255,255,255,0.25)` |
| 主文字 / 次文字 | `#FFFFFF` / `rgba(255,255,255,0.6)` |
| 品牌渐变 | `#FEDA75 → #FA7E1E → #D62976 → #962FBF → #4F5BD5`（ins 式，45°） |
| 圆角 | 卡片 24、展品 28、按钮 16、胶囊/底栏 999 |
| 间距 | 4 的倍数；页面左右 16 |
| 阴影（悬浮） | `0 20 40 rgba(0,0,0,0.6)` + 作品主色光晕 |

**底部导航栏**：悬浮胶囊（距底部安全区 12，左右 24），毛玻璃底；选中项后方有一块更亮的毛玻璃胶囊 + 渐变描边，切换时以弹簧动画（damping≈18, stiffness≈180）平移并伴随轻微宽度拉伸，选中图标变为渐变色，配合轻触感反馈。

**展览浏览页动效**：当前卡片 scale 1、z 前置；相邻卡片 scale 0.86、rotateY ±18°、透明度 0.5、轻微下沉；滑动时跟手插值；松手弹簧归位；背景为当前作品的高斯模糊大图 + 暗化，切换时交叉淡入；当前卡片 4 秒周期 ±3px 呼吸浮动。

## 9. 技术栈（推荐，待确认后安装）

| 层 | 选择 | 用途 |
|---|---|---|
| 跨端框架 | **Expo（React Native）+ TypeScript** | 一套代码出 iOS / Android；Windows 上可用 Expo Go 直接在 iPhone 真机调试，iOS 包用 EAS 云构建 |
| 路由 | Expo Router | 底部 Tab + 栈导航 |
| 动效/手势 | react-native-reanimated、react-native-gesture-handler | 滑动底栏指示器、3D 纵深切换 |
| 毛玻璃/渐变 | expo-blur、expo-linear-gradient、（可选）@shopify/react-native-skia | 玻璃面、ins 渐变、光晕 |
| 图片 | expo-image、expo-image-picker、expo-image-manipulator | 缓存显示、选图、压缩 |
| 通知/触感 | expo-notifications、expo-haptics | 推送提醒、切换反馈 |
| 数据 | TanStack Query + Zustand | 服务端状态缓存 + 本地状态 |
| 后端 | **Supabase**：Postgres + RLS、Auth、Storage（签名 URL）、Realtime、pg_cron、Edge Functions | 权限矩阵服务端强制、状态定时流转、30 分钟提醒、私信实时 |

注意：Android 上的实时模糊性能弱于 iOS，需为低端机提供「半透明不模糊」降级。
